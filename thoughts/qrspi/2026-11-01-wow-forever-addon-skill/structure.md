# Structure Outline

## Approach
This repo becomes a plugin. Its one skill is `skills/wow-forever-addon/` (abbreviated **SK** below). The skill's API knowledge is generated from Gethe `forever` docs plus curated notes, and its offline gate is `lint.sh` and `test.sh` run under `luajit`. Each phase leaves something you can install and run, following design.md's milestone order (M1 → M2 → M3 → M6 → M5 → M4 → M7).

Gate after each phase:
- `scripts/check.sh`: `quick_validate`, lint and tests over SK and `examples/`.
- From Phase 2 on, an in-game `/reload` check. That check is pending until Forever launches on 2026-11-04.

## Phase 0: Installable plugin skeleton (M1 start)
After this phase the plugin installs and the skill triggers, though it does little yet. The license is MIT.

**Files**:
- Plugin manifests: `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`
- Skill: `SK/SKILL.md` (frontmatter, trigger description, a "Read before you touch" table with stub rows)
- Repo root: `LICENSE` (MIT replaces GPL-3.0), `README.md` (install), `scripts/check.sh`, `.gitignore`

**Key changes**:
- `plugin.json { name: "wow-forever-addon", version: "0.1.0", description, author, license: "MIT" }`
- SKILL.md frontmatter `{ name: wow-forever-addon, description (≤1024 chars, pushy), license: MIT }`
- `scripts/check.sh` runs `quick_validate.py SK`, plus the lint and test steps once they exist. It exits non-zero on any failure.

**Verify**:
- `scripts/check.sh` exits 0.
- `brew install luajit luacheck` succeeds.
- `claude --plugin-dir .` lists `wow-forever-addon:wow-forever-addon`.
- Manual: "help me write a WoW Forever addon" triggers the skill.

## Phase 1: Forever API knowledge + lint (M1/M2)
After this phase, Claude can lint any Lua file against the real Forever API surface, and never-emit calls fail.

**Files**:
- Generator: `SK/scripts/gen-api.sh`, `SK/scripts/gen_api.lua`
- Generated by the script:
  - `SK/references/forever-api-index.md`
  - `SK/templates/luacheck/forever-globals.lua`
- Hand-written:
  - Lint setup: `SK/templates/luacheck/.luacheckrc`, `SK/scripts/lint.sh`
  - References: `SK/references/forever-api-notes.md`, `SK/references/toc-format.md` (the single Interface source)
- Fixtures: `SK/scripts/fixtures/{good,bad}.lua`

**Key changes**:
- `gen-api.sh [--ref forever] [--src <wow-ui-source checkout>]`:
  - Shallow-clones the `forever` branch.
  - Runs `luajit gen_api.lua <src> <out-dir>`. That script loads `Blizzard_APIDocumentationGenerated/*.lua` with a stubbed `APIDocumentation:AddDocumentationTable(t)` collector.
  - Writes the index and the std, both stamped with source commit and date.
- `forever-globals.lua` returns `stds.forever = { read_globals = { C_Container = { fields = {...} }, ... } }`.
- `.luacheckrc` holds:
  - `std = "lua51+forever"`, `max_line_length = false`, `exclude_files = {"**/Libs"}`
  - `ignore = {"211","212","213","212/self"}`
  - `not_globals = { <never-emit list from forever-api-notes.md> }`
- FrameXML and global functions missing from the docs (e.g. `CreateFrame`, `UIParent`, `SlashCmdList`, `strsplit`, `wipe`) go in a hand-kept `extra_globals` table inside gen_api.lua.
- `lint.sh [path...]` runs luacheck with that config and exits luacheck's status.
- `toc-format.md` carries the line `Interface: 16001 (as of 2026-11-01, beta; confirm via /dump select(4, GetBuildInfo()))`.

**Verify**:
- `lint.sh fixtures/good.lua` exits 0. `good.lua` uses `C_Container.GetContainerItemInfo`, `C_Timer.After` and `CreateFrame`.
- `lint.sh fixtures/bad.lua` fails. `bad.lua` uses a never-emit global and an invented `C_Fake.Foo`.
- The index lists `C_Container`, `C_UnitAuras` and `C_SwingTimer`.

## Phase 2: Vanilla scaffold (M2)
After this phase, `scaffold.sh` produces a loadable vanilla addon that passes lint.

**Files**:
- `SK/templates/vanilla/{__NAME__.toc, Core.lua}` and template `README.addon.md`, `CHANGELOG.md`, `LICENSE.MIT`
- `SK/scripts/scaffold.sh`
- References: `SK/references/saved-variables.md`, `SK/references/events.md` (core lifecycle events)
- SKILL.md: workflow §7.1 (new addon, simple), plus the in-game checklist

**Key changes**:
- `scaffold.sh <Name> [--ace3] [--pattern event|timer|ui|ldb|tooltip]... [--license MIT|none] [--dest DIR]`:
  - Copies the template and replaces `__NAME__`, `__INTERFACE__` (read from toc-format.md), `__SLASH__` and `__AUTHOR__`.
  - Drops pattern blocks that weren't selected. Blocks are delimited by `--@pattern:x@ … --@end-pattern@`.
- Core.lua contract:
  - `local addonName, ns = ...`
  - Event frame with an `OnEvent` → `self[event](self, ...)` dispatcher.
  - `ADDON_LOADED` (when `arg1 == addonName`): merge defaults, then `ns.Migrate(db, fromVersion)`.
  - `PLAYER_LOGIN` hook.
  - `SLASH_<KEY>1` handler and `/name debug` toggle.
- TOC fields: `Interface`, `Title`, `Notes`, `Author`, `Version: @project-version@`, `SavedVariables`, `SavedVariablesPerCharacter`, `X-Curse-Project-ID`, `X-Wago-ID`.

**Verify**:
- `scaffold.sh Demo --dest /tmp/x && lint.sh /tmp/x/Demo` passes, once with no flags and once for each `--pattern`.
- Manual (after launch): copy to `Interface/AddOns`, `/reload` with no errors, `/demo debug` toggles.

## Phase 3: Mock harness + tests + example addon (M3)
After this phase, scaffolded addons ship with tests that pass offline, and `examples/` holds one worked addon.

**Files**:
- `SK/scripts/wowmock/{init.lua, frames.lua, events.lua, timer.lua, unit.lua, slash.lua, savedvars.lua, toc.lua, runner.lua}`
- `SK/scripts/test.sh`
- `SK/templates/vanilla/tests/core_spec.lua`
- `examples/TooltipItemLevel/` (scaffolded with the tooltip pattern, plus tests)

**Key changes**:
- Environment API:
  - `wowmock.new_env(opts?) -> Env`
  - `Env:load_addon(dir) -> ns`: parses the TOC, then loads files in order with `(addonName, ns)` varargs and sandboxed `_G`. Fires `ADDON_LOADED` after saved variables load.
  - `Env:fire(event, ...)`, `Env:advance(seconds)` (drives `C_Timer`/`GetTime`), `Env:slash("/cmd args")`
  - `Env:saved() -> table`, `Env:reload()` (saves, then reloads with the same saved variables)
- Frame stub: `CreateFrame(type, name?, parent?, template?) -> Frame` with methods `RegisterEvent`, `UnregisterEvent`, `SetScript`, `GetScript`, `Show`, `Hide`, `IsShown`, `SetPoint`, `SetSize`, `CreateFontString`.
  - Any unknown method raises "wowmock: unimplemented Frame:X", which is how the stub grows from test failures.
- Runner: `describe/it/before_each`, `assert.equals/truthy/falsy/same/errors`. Exits non-zero on failure.
- `test.sh [addon-dir]` runs `luajit runner.lua <dir>/tests/*_spec.lua`.
- `references/testing.md` states what the harness does **not** cover: taint, rendering, secure frames, secret values. It names hogsim/wowless as a future option.

**Verify**:
- `test.sh examples/TooltipItemLevel` passes.
- A fresh `scaffold.sh` addon passes `test.sh`. Its tests cover load, saved-variable defaults and the slash command.
- `check.sh` exits 0.

## Phase 4: Ace3 path (M2 completion)
After this phase, `scaffold.sh --ace3` produces an Ace addon with an options panel and profiles, and it passes lint and tests.

**Files**:
- `SK/templates/ace3/{__NAME__.toc, embeds.xml, Core.lua, Options.lua, tests/core_spec.lua}`
- `SK/scripts/wowmock/ace.lua`
- `SK/references/ace3-vs-vanilla.md`
- SKILL.md: the decision rule

**Key changes**:
- Template structure:
  - `NewAddon(name, "AceConsole-3.0", "AceEvent-3.0")`
  - `OnInitialize`: AceDB with `defaults.profile`, AceConfig and AceDBOptions, chat command
  - `OnEnable`: registers events
- `embeds.xml` loads LibStub first.
- `ace.lua` provides `LibStub` plus minimal AceAddon, AceDB, AceEvent and AceConsole stubs, enough to run OnInitialize and OnEnable, defaults and profile get/set, events and the chat command.
- The decision rule follows PRD §5.1. The chosen option and its reason are written into the generated README.

**Verify**:
- `scaffold.sh AceDemo --ace3` passes both `lint.sh` and `test.sh`.
- Manual (after launch): with libs packaged (Phase 7) or dropped in by hand, `/reload` shows no errors and the options panel opens.

## Phase 5: QRSPI handoff (M6)
After this phase, a non-trivial addon request is routed into QRSPI, with the skill supplying WoW-specific inputs at each phase.

**Files**:
- `SK/references/qrspi-handoff.md`: the only place the `/qrspi-plan-toolkit:*` command names appear
- `SK/templates/qrspi/{task.template.md, questions.wow.md, design-questions.wow.md}`
- SKILL.md: routing table, detection, and fallback

**Key changes**:
- Detection: is `qrspi-plan-toolkit:1-question` in the available skills list? If yes, use the routing table from PRD §5.7. If no, use the direct workflow plus a one-line install hint.
- Per-phase inputs:
  - questions.wow.md holds the standing neutral questions.
  - The design-questions file lists the Ace3/vanilla, event/OnUpdate, saved-variable scope, secure-frame and UI-framework questions, each pointing at the `references/` file that answers it.
  - Plan rule: check every code snippet in a plan against `not_globals`.

**Verify**:
- `check.sh` exits 0.
- Manual: take one small addon through `1-question` → `3-design` and confirm the WoW inputs appear and `questions.md` stays neutral.
- Phase 9 finishes the full 1→8 run.

## Phase 6: Debug, review, performance, gap analysis (M5)
After this phase, the skill can triage a BugSack trace or an addon folder and run a gap analysis against CurseForge.

**Files**:
- `SK/references/{taint-and-secure.md, performance.md, widgets.md, curseforge-gap-analysis.md}`
- SKILL.md: §7.2 debug, §7.3 API question, gap-analysis step
- `SK/scripts/fixtures/buggy/` (a seeded-fault addon)

**Key changes**:
- A debug classification table: nil access, taint, API drift, load order, perf. Each row maps to a reference file and a regression-test recipe in wowmock.
- `review` checklist: global leaks (luacheck 111/112/113), throttling on unthrottled `OnUpdate`, saved variables read before `ADDON_LOADED`, never-emit APIs, frames recreated on every call.
- Gap-analysis report template: up to 5 matches, last update, whether Forever is in the flavor list, the gaps, and a verdict (use / fork / build), with "unverified" fallbacks.

**Verify**:
- `lint.sh` and `test.sh` flag every seeded fault in `fixtures/buggy`.
- Manual: one real debugging session, and one gap-analysis run on a sample idea.

## Phase 7: Release pipeline (M4)
After this phase, pushing a tag on the example addon packages it and uploads it to CurseForge and Wago.

**Files**:
- `SK/templates/{.pkgmeta, release.yml}`
- `SK/references/release-pipeline.md` (including the `/release` checklist)
- `examples/TooltipItemLevel/{.pkgmeta, .github/workflows/release.yml}`
- Repo root: `.github/workflows/ci.yml` (`check.sh` in CI via `leafo/gh-actions-lua` with luajit)

**Key changes**:
- `.pkgmeta`:
  - `package-as`, `manual-changelog: CHANGELOG.md`, `enable-nolib-creation: no`
  - `ignore: [tests, thoughts, .github, .luacheckrc, .pkgmeta]`
  - Per-library Ace3 `externals` (Ace3 template only)
- `release.yml`:
  - Triggered by `on: push: tags: ['v*']`
  - Checkout with `fetch-depth: 0`, then `BigWigsMods/packager@v2`
  - Env `CF_API_TOKEN`, `WAGO_API_TOKEN`, `GH_API_TOKEN`

**Verify**:
- A local `release.sh -d -z` dry run (no upload) builds a zip with no `tests/` or `thoughts/` folders and with the TOC version substituted.
- Owner-gated: a real tag on the example uploads to CurseForge and Wago.

## Testing Checkpoints
- **After P0:** the plugin installs, the skill triggers, and `check.sh` is green on frontmatter.
- **After P1:** generated Forever globals exist, and lint passes good code and rejects never-emit and invented APIs.
- **After P2:** a scaffolded vanilla addon is lint-green. In-game `/reload` is pending until launch.
- **After P3:** the vanilla scaffold and the example addon are test-green offline. **This is the minimum useful skill.**
- **After P4:** the Ace3 scaffold is lint- and test-green.
- **After P5:** non-trivial requests route to QRSPI with WoW inputs.
- **After P6:** debug, review and gap-analysis flows are documented and exercised.
- **After P7:** the release zip builds locally, and the live upload is owner-gated.
- **After P8:** evals pass and v1.0.0 is tagged.
- **Post-launch (2026-11-04):** confirm the live Interface value, rerun `gen-api.sh`, and repeat the in-game checks from P2 and P4.

**Not vertically sliceable:** the reference prose (events, widgets and so on) lands piecemeal with whichever phase first needs it. There is no "all docs" phase.
